# September 10, 2026: The P0 Probe Exposed a Cancellation Propagation Gap

[简体中文](2026-09-10.md) · **English**

## Why we ran this probe

One Agent task can contain several model requests and tool calls. Commercial access requires authorization, billing, and auditability, so we first needed to understand how each request is identified, when it retries, whether a failure may already have incurred cost, and whether stopping a task actually stops upstream work.

## What was completed

- Ran an isolated experiment with a pinned real local runtime and a loopback mock upstream.
- Covered the complete cycle of text, side-effect-free tools, tool results, and follow-up text.
- Covered identity fields, rate limits, expired credentials, interrupted responses, missing usage, and user cancellation.
- 15 of 16 final cases passed; one failed.
- Used no real model credentials, paid requests, database migrations, or production deployments.

## What we found

The failed case involved user cancellation. The local task entered an interrupted state, but the upstream connection did not close within the observation window. Therefore, an interface state cannot prove that the provider stopped generating or stopped billing.

An added explicit-abort prototype closed the corresponding connection and showed that a minimal transport-boundary solution is feasible. The prototype is not part of the everyday Agent path, so the result remains 15/16 rather than being rewritten as a complete P0 pass.

## Current decisions

- Keep the existing Agent core.
- Record cancellation propagation as a known limit instead of continuing a dedicated fix now.
- In future commercial access, distinguish tasks, individual model operations, and actual dispatch attempts.
- Store request content, acceptance, and billing state separately; an identical request body cannot prove whether work was duplicated.

## Still to verify

- The actual AI gateway's protocol capabilities and log correlation.
- The real relationship among provider acceptance, cancellation, and metering.
- Identity ownership and atomic wallet admission under multi-company, multi-member concurrency.

This journal publishes verification outcomes and product impact without exposing internal interfaces, environment addresses, test credentials, or reproducible implementation details.
