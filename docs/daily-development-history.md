这里按私人源码仓库的实际提交日记录 PAWSON AI 的连续变化。普通提交日简要说明，大规模功能、架构或版本变化展开为约 7–8 条；没有提交的日期不列入这条时间线。

## 2026 年 7 月

### 2026-07-27｜从本地工具进入商业客户端基础

- 私人源码仓库形成首批正式提交，开始保留连续演进历史。
- 建立支付配置、管理接口与控制台基础。
- 接入微信 Native 支付的签名、通知和结果验证链路。
- 移除无法形成权威结算证据的人工支付路径。
- 打包客户端开始连接云端控制中心。
- 增加设备、套餐和后台服务配置边界。
- 发布 1.0.5 本地验收版本，同时明确仍存在的上线缺口。

### 2026-07-28｜完善账户、发布和生产可靠性

- 增加供应商模型发现，减少固定模型配置带来的维护成本。
- 建立桌面版本发布、上传进度和管理员自助管理能力。
- 支持管理员修改密码，并自动刷新过期会话。
- 统一工具页面容器和结果预览，减少界面跳动。
- 延长图片任务的合理等待时间，并优化打包环境连接。
- 防止重复付费提交，提前预热本地抠图运行时。
- 形成软件著作权和支付交接材料，但不把文档当成业务验收结果。

### 2026-07-30｜统一商品图片生产工作区

- 将分散的生成、任务选择和结果展示收进统一生产工作区。
- 为单图和结果画廊增加“继续处理”，支持流转到后续图片工具。
- 建立幂等结果交接，避免重复点击产生重复操作。
- 恢复任务参数时不重复计费，并阻止已拒绝请求盲目重试。
- 连接恢复后主动校准任务状态，失败信息变得可操作。
- 校验导出文件和生产错误分类，保留已有有效结果。
- 完成 1.1.0 准备，产品从功能集合走向连续生产链路。

### 2026-07-31｜形成黄金生产链路

- 定义一条可重复验收的核心图片生产路径。
- 增加生产旅程导航和状态模型。
- 页面跳转开始携带明确上下文，同时限制不安全的跨步骤操作。

## 2026 年 8 月

### 2026-08-01｜本地印花提取进入内部测试

- 准备 1.1.1 内部测试版本。
- 建立本地上衣图案提取方案。
- 修正为只提取用户选择的印花区域。
- 随后准备 1.1.2 印花提取测试版本。

### 2026-08-02｜生产流程转向项目中心

- 将图片生产工作区改为围绕项目保存素材、参数、任务和结果。
- 明确模型路由的职责边界，避免页面各自决定供应商。
- 停止重试被服务商明确拒绝的请求。
- 形成新的对齐实施计划和发布交接记录。
- 准备 1.1.3 版本。
- 项目化成为后续商品详情、数据资产和长期任务的基础。

### 2026-08-06｜调整开发模型路由

- 更新 Codex 开发任务的模型路由配置。
- 这属于开发工具调整，不改变产品对外能力。

### 2026-08-09｜保存经营闭环稳定基线

- 在后续并行开发前保存可恢复检查点。
- 检查点用于保护已有经营闭环，不能单独代表新增功能发布。

### 2026-08-10｜保存报告交付稳定基线

- 在报告体验继续调整前保存企业协作交付检查点。
- 为后续阅读体验和交付路径优化提供明确回退位置。

### 2026-08-12｜报告开始成为真实交付物

- 改进报告中心的阅读、整理和交付体验。
- 连接企业协作工具的报告输出路径。
- 规范跨境 Worker 产物，避免临时结果污染正式资产。
- 补充平台与跨境模块交接记录。
- 详细记录：[报告开始成为真实交付物](../updates/2026-08-12.md)。

### 2026-08-13｜保存 RC 功能稳定检查点

- 在夜间界面优化前保存已验证功能基线。
- 检查点主要用于恢复和对比，没有扩大公开能力声明。

### 2026-08-16｜为商品详情规划保存基线

- 在商品详情策划器开发前保存 PAWSON RC 稳定检查点。
- 现有报告、任务和生产能力获得明确回退位置。

### 2026-08-18｜PAWSON Agent v0.5 检查点

- 保存 Agent v0.5 阶段性版本。
- 产品开始把图片生产和经营能力汇入统一会话入口。
- 这一版本仍属于中间检查点，运行恢复和真实任务闭环继续完善。

### 2026-08-20｜补强视觉回答与传输恢复

- 让视觉回答优先展示用户可见证据。
- 建立传输观测和恢复方案。
- 保存视觉运行与传输恢复检查点。
- 为次日 Agent MVP 稳定基线提供故障证据。

### 2026-08-21｜Agent MVP 成为产品新主线

- 建立持续对话和任务状态基础。
- 将专业能力与会话上下文结合。
- 稳定运行失败后的恢复和输入保留。
- 保存 PAWSON Agent MVP v0.5 基线。
- 详细记录：[Agent MVP 成为产品新主线](../updates/2026-08-21.md)。

### 2026-08-22｜建立多任务和上下文基础

- 建立 PAWSON 多任务基础，使不同任务拥有独立状态。
- 完善会话历史和 Agent 交互体验。
- 稳定并发任务和专家会话。
- 加强 Skill、专家和会话边界。
- 保存本地验收与上下文检查点。
- 为数据、知识和采集能力进入 Agent 上下文做准备。

### 2026-08-23｜数据、知识和网页采集打底

- 建立核心数据基础。
- 建立知识能力基础。
- 接入网页采集核心结构，并保留来源关系。
- 优化专家中心体验。
- 精简 Agent 长期规则，减少不同任务间的执行歧义。

### 2026-08-24｜数据资产开始成为产品能力

- 建立 PAWSON 2.0 产品表面基础。
- 数据资产开始读取真实核心数据，而不是页面占位内容。
- 知识能力接入同一核心数据来源。
- 经营分析可以显式登记数据资产。
- 建立数据资产和知识产品读取模型。
- 修复页面切换和应用重启后的状态保留。
- 优化数据资产总览，同时保持来源与访问边界。

### 2026-08-25｜知识库管理与界面控件统一

- 建立真实知识库创建流程和生命周期管理。
- 支持把数据资产加入知识库并安全移除。
- 为知识条目增加稳定展示身份，避免重名混淆。
- 管理专家对知识库的访问范围。
- 重塑专家中心和知识管理界面。
- 统一生产、导入、任务、经营和列表下拉控件。
- 对齐数据与生产工作区视觉，并改善全局洞察可读性。
- 修复知识管理访问边界，避免界面状态扩大权限。

### 2026-08-26｜采集、数据和商品项目开始连接

- 数据采集中心进入正式产品界面。
- 建立持久化浏览器采集运行时和安全商品数据服务。
- 将商品趋势、渠道和流量信息转成可读取产品能力。
- 采集结果可以登记为带来源的数据资产。
- 商品详情形成隔离、可编辑的项目原型。
- 文本与图片生成开始服务商品详情草稿。
- 优化专家形象和会话栏，使专业方法更易识别。
- 详细记录：[采集、数据和商品项目开始连接](../updates/2026-08-26.md)。

### 2026-08-27｜统一工作区与专家创建

- 合并 PAWSON 工作区外壳，减少模块间切换断裂。
- 建立专家创建向导的数据模型和完整界面。
- 商品详情海报可以独立编辑。
- 改进经营信号和导航表达。
- 对齐采集、搜索和数据页面的视觉层级。
- 更新当前状态和任务交接记录。
- 清理已退出主线的旧商品详情契约。

### 2026-08-28｜Agent 开始通用化并接入文件

- 将 Agent 从固定问答升级为工具驱动的通用核心。
- 增加有界文件输入，限制类型、大小和工作区范围。
- 传输失败开始提供明确恢复入口。
- 敏感工具在用户批准后继续执行，而不是自动绕过。
- Agent SDK 接管部分外部工具边界。
- 完成集成验证并修复恢复问题。
- 这一天为后续命令、长任务和文件交付建立基础。

### 2026-08-29｜全局助手和可恢复商品详情项目

- 建立商品详情项目格式和自动保存历史。
- 支持项目导入、导出、复制、恢复和继续编辑。
- 建立项目库 API 和可视化项目列表。
- 全局助手使用隔离会话读取当前页面上下文。
- 页面助手与正式主任务保持边界，避免污染会话历史。
- 强化供应商恢复、全局洞察分析和草稿隔离。
- 减少空闲计算和重复商业任务轮询。
- 合并多条工作线并通过构建契约检查。

### 2026-08-30｜收尾演示与恢复细节

- 增加产品演示指南。
- 压缩会话启动状态，减少冗余恢复信息。
- 继续修复供应商重试和恢复边界。

## 2026 年 9 月

### 2026-09-01｜Agent 开始处理文件和长任务

- 建立受控本地命令合同和命令行优先的执行模式。
- Agent 可以执行有界命令并验证真实生成文件。
- 长任务能够保存过程状态、停止、恢复并保留有效产物。
- 文件卡片支持打开，应用重启后仍可访问。
- 加载文档、表格等办公 Skill，并显示加载状态。
- 建立外部 Skill 注册、发现、检查和挂载流程。
- 收紧 GitHub Skill 检查范围，减少不必要的模型轮次。
- 详细记录：[Agent 从回答问题走向处理文件和长任务](../updates/2026-09-01.md)。

### 2026-09-02｜接入正式 NEW PAWSON AI 运行时

- 增加官方 NEW PAWSON AI Runtime。
- 保留旧网页研究能力作为迁移验收基线。
- 新旧路径暂时并存，后续能力按真实验收逐步迁移。

### 2026-09-04｜建立可插拔专家包

- 完成正式运行时集成。
- 定义可插拔专家架构和专家人格包模板。
- 建立任务范围内的专家中心。
- 注册内置专家 Skill。
- 增加首个视觉诊断专家包“凌镜”。
- 保存任务能力，使恢复后的会话仍知道可用专家。
- 为经营分析和文档交付专家沿用同一结构。

### 2026-09-05｜完成三类专家与本地个人中心

- 建立任务范围内的专家协作工作区。
- 完成经营分析和文档交付专家包。
- 视觉、经营和文档方法进入同一主任务。
- 建立本地用户资料合同和安全持久化。
- 增加头像预设、资料编辑和侧栏个人中心。
- 稳定 AI 与商品工作流，修正头像视觉方向。
- 保存专家包和当前 PAWSON 状态交接记录。

### 2026-09-06｜首个 Codex 协作里程碑

- 官方运行链路、线程恢复和任务内补充输入形成闭环。
- 三类专家方法可以在同一任务中协作。
- 经营上下文、图片和文件输入进入统一工作区。
- 图片恢复、工具过程和诊断证据得到补强。
- 365 个测试文件、2342 项测试通过。
- TypeScript、桌面界面和生产构建通过。
- 详细记录：[从工具集合到综合 Agent 工作台](../updates/2026-09-06.md)。

### 2026-09-07｜三项架构收口

- 统一任务交互状态，避免维护第二份运行事实。
- 可信经营上下文改为用户可控的只读注入。
- 运行观测只保留有界安全元数据。
- 根据实机体验移除页面跳转、跨功能预填和内部操作卡。
- 项目从大规模核心改造转入小步验收和缺陷修复。
- 373 个测试文件、2389 项测试与完整生产构建通过。
- 详细记录：[三项架构完成收口](../updates/2026-09-07.md)。

<a id="day-2026-09-08"></a>

### 2026-09-08｜通用 AI 网关首条链路

- 退役上一代多供应商能力路由，保留必要兼容数据。
- 建立供应商中立的版本化能力合同。
- 建立最小权限短期签名授权和公开验签边界。
- 桌面 Agent、文本、生图和图片编辑开始复用同一网关合同。
- 长期供应商密钥不进入桌面界面、普通日志或控制中心响应。
- 千问首条真实文本链路与消费者授权完成实机验收。
- 详细记录：[通用 AI 网关完成首条链路](../updates/2026-09-08.md)。

### 2026-09-09｜新 Agent 能力恢复与 2.0 发布

- 桌面产品、控制中心、报告和采集扩展统一为“派笙 AI 中台 2.0”。
- 建立版本化模型目录和会话级模型选择。
- 控制中心为企业会话签发短期模型池，桌面不保存长期供应商凭证。
- 恢复联网搜索、公开网页读取和可点击来源。
- 恢复专家身份、全局页面助手和结构化文件交付。
- 旧 Agent Runtime、本地供应商直连和旧数据主链路正式退出。
- 隔离 2.0 数据目录，同时保持账户、积分和更新协议兼容。
- 详细记录：[进入派笙 AI 中台 2.0 阶段](../updates/2026-09-09.md)。

## 记录原则

这份逐日历程只写能够由提交、检查点、测试、构建、真实文件或实机验收支持的内容。没有提交的日期直接省略；计划、草稿和界面提示不会被改写为完成。私人源码、完整架构、内部地址、凭证、客户数据和可复刻实现不会进入公开记录。
